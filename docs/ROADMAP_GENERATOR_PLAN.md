# Skillora Roadmap Generator Plan

## 1. Goal

Build a deterministic Roadmap Generator that turns a student's skill gaps into a personalized learning roadmap.

The feature should work independently from CV scanning so it does not conflict with the CV extraction branch.

Core input:

```txt
target_role + gap_items + teacher_resources
```

Core output:

```txt
roadmap phases + learning steps + recommended resources + resource gap alerts
```

The roadmap must be generated by backend rules and configuration. AI may only be used later to polish student-facing wording, not to decide scores, gaps, priority, severity, phase order, or recommended actions.

## 2. Problem This Solves

Students often do not know:

- Which skills they are missing for a target career.
- Which missing skills are most important.
- What to learn first.
- What concrete practice or project to do.
- Which teacher-provided resources can help them close the gap.

Skillora should convert a readiness diagnosis into an action plan:

```txt
Gap -> Roadmap -> Practice -> Evidence -> Updated readiness
```

## 3. MVP Scope

For the first implementation, build:

- `POST /roadmaps/generate`
- Role and skill configuration.
- Rule-based roadmap generation.
- Resource matching.
- Missing-resource alerts.
- Swagger DTOs and examples.

Do not build first:

- Full course builder.
- LMS features.
- Complex authentication.
- Payment or marketplace.
- AI-generated scoring or autonomous AI grading.

## 4. Recommended Backend Location

Create a standalone module:

```txt
apps/api/src/roadmap/
  roadmap.module.ts
  roadmap.controller.ts
  roadmap.service.ts
  dto/
    generate-roadmap-request.dto.ts
    roadmap-response.dto.ts
  config/
    skill-taxonomy.config.ts
    role-profiles.config.ts
    phase-templates.config.ts
    skill-templates.config.ts
    roadmap-rules.config.ts
```

Avoid modifying `analysis.service.ts` at first. After the CV/gap branch is ready, `/analyses` can call `RoadmapService.generateRoadmap()`.

## 6. Configuration Model

Do not hardcode one roadmap per role. Use reusable configuration:

```txt
Skill Taxonomy
+ Role Profiles
+ Phase Templates
+ Skill Templates
+ Roadmap Rules
```

This lets the same engine support software, data, AI, marketing, business, design, and other career domains.

### 6.1 Skill Taxonomy

Skill taxonomy defines reusable skills.

Example:

```ts

    name: "REST API",
    domain: "software",

    defaultPhase: "core",
    prerequisites: ["programming_fundamentals", "http_basics"],

  sql: {
    name: "SQL",
    domain: "data",
    category: "technical",
    defaultPhase: "foundation",
```

Use common phases across roles:

### 6.4 Skill Templates

Skill templates define what to do for each skill.

Example:

```ts
export const skillTemplates = {
  rest_api: {
    theory: "Learn HTTP methods, REST conventions, status codes, and request validation",
    practice: "Build CRUD endpoints for a task management API",
    assessment: "Explain endpoint design, validation, and error handling",
    deliverable: "GitHub repository with API routes, README, and sample requests"
  },
  seo: {
    theory: "Learn keyword research, search intent, on-page SEO, and basic technical SEO",
    practice: "Create an SEO plan for a blog article or landing page",
    assessment: "Explain keyword choice, search intent, and optimization decisions",
    deliverable: "SEO brief with target keywords, outline, title, meta description, and internal links"
  }
};
```

If a skill has no specific template, use a generic fallback template:

```txt
Learn the concept.
Complete a small practice task.
Create a deliverable.
Review with a checklist.
```

## 7. Roadmap Generation Rules

### 7.1 Priority Score

Sort gaps by deterministic priority:

```txt
priority = severityWeight + currentLevelWeight + roleImportance + prerequisiteBoost
```

Suggested weights:

```ts
severityWeight = {
  high: 3,
  medium: 2,
  low: 1
};

currentLevelWeight = {
  missing: 2,
  partial: 1,
  weak_evidence: 1
};
```

### 7.2 Step Generation

Rules:

```txt
high + missing:
- theory
- practice
- assessment
- deliverable

medium or partial:
- practice
- assessment
- deliverable

low:
- review
- small practice
```

### 7.3 Phase Grouping

Group gaps by skill phase:

```txt
foundation -> Foundation Skills
core -> Core Role Skills
applied_project -> Applied Practice Project
portfolio -> Portfolio and Interview Readiness
```

If `starting_level` is `non_it_transition` or `career_transition`, prepend a transition phase.

### 7.4 Starting Level

Use starting level to avoid giving an advanced roadmap to a student with no related background.

Suggested values:

```txt
non_it_transition
beginner
intermediate
role_ready
```

Example:

```txt
non_it_transition + backend_developer
=> transition phase + software foundation + backend core + portfolio
```

```txt
beginner + digital_marketing_specialist
=> marketing foundation + core marketing skills + campaign project + portfolio case study
```

## 8. Resource Matching

Teacher resources enrich roadmap steps but do not decide the roadmap.

Resource statuses:

```txt
matched
partial_match
missing_internal_resource
```

Matching rules:

```txt
matched:
- resource.skill_tags contains the skill name or skill id
- difficulty is appropriate for current level

partial_match:
- resource tags match the same domain or related category

missing_internal_resource:
- no suitable teacher resource found
```

If no resource is available:

- Keep the roadmap step.
- Set `resources` to an empty array.
- Set `resource_status` to `missing_internal_resource`.
- Add a `resource_gap_alert` for teachers.

Do not invent external links.

## 9. Handling Non-IT Students Choosing IT Roles

If a student has little or no IT evidence but selects an IT role, do not block them.

Instead, generate a transition roadmap:

```txt
Phase 0: Career Transition Foundations
Phase 1: Programming Foundation
Phase 2: Role Core Skills
Phase 3: Applied Project
Phase 4: Portfolio Readiness
```

This is controlled by `starting_level`, not by AI.

Example:

```txt
non_it_transition + backend_developer
=> 10-12 week roadmap
```

## 10. Marketing Support

The engine should support marketing by adding marketing skills and role profiles, not by changing the roadmap logic.

Example marketing phases:

```txt
Phase 1: Marketing Foundations
Phase 2: Core Digital Marketing Skills

```

Example marketing deliverables:

## 14. Acceptance Criteria

The feature is ready for MVP when:

- `POST /roadmaps/generate` accepts target role, gap items, and resources.
- It returns deterministic roadmap phases.
- It works even when no teacher resources exist.
- Missing resources generate teacher-facing alerts.
- Roadmaps differ by role and starting level.
- The same engine can support IT, data, AI, and marketing roles through config.
- Swagger clearly documents request and response shapes.
- No LLM decides gap severity, readiness score, phase order, or learning priority.

## 16. Updated Direction: Backend Scoring + Gemini Lesson Planner

The roadmap feature now follows a hybrid approach:

```txt
CV/transcript result
-> gap_items
-> backend deterministic scoring
-> improvement_items with recommended weeks
-> locked Gemini prompt
-> 4-week lesson plan
```

Backend remains responsible for:

- Calculating improvement scores.
- Deciding skill priority.
- Assigning each skill to week 1-4.
- Preserving severity, current level, target level, and role importance.
- Creating resource gap alerts.
- Creating optional external course search suggestions.

Gemini should only generate:

- Lesson titles.
- Activities.
- Practice tasks.
- Deliverables.
- Student-friendly wording.
- Optional course usage notes.

Gemini must not:

- Add skills outside `improvement_items`.
- Change scores.
- Change severity.
- Change recommended week.
- Decide readiness.
- Invent teacher resources.

Current implementation returns:

```txt
improvement_items
phases
four_week_plan
lesson_source
ai_prompt
resource_gap_alerts
```

`lesson_source` is currently `backend_fallback`. After Gemini API integration, this can become `ai_generated` when a valid Gemini JSON response is returned and validated.

External course suggestions are currently search-based suggestions across providers such as Coursera, edX, Udemy, and YouTube. They are optional enrichment only. Teacher resources should remain preferred when available.
